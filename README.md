## 1. 这是什么

一个纯静态个人档案网站，六个板块：Research / Works / Universe / Characters / About / Contact。

- **设计源**：`my web figma.svg`（19MB，已放进项目根目录，最终依据）

- **技术栈**：无框架、无构建依赖的纯 HTML / CSS / JS。只有一个 PowerShell 脚本做静态生成
- **运行方式**：VS Code 的 **Live Server**（用户实际用的就是这个）；`file://` 直接打开也做了兼容
- **代码在哪**：本机 `E:\GitHub\My-web`（GitHub Desktop 克隆，仓库 `github.com/JianghaoPeng06/My-web`，只有 `main` 一个分支），
  推送后 Cloudflare Pages 自动上线到 `https://jasperpeng.uk`。**直接在这个文件夹里改**，流程见 §1b

## 1b. 工作流程（2026-10-04 定下来的）

**只在 `E:\GitHub\My-web` 一个地方改，不要另建副本再搬回来。**

1. 改之前：GitHub Desktop 里先点 **Fetch origin**，有更新就 **Pull**
2. 在文件夹里改（自己改或让 Claude 改），浏览器里预览确认
3. 满意 → 想一下要不要改**版本号**（见 §10「版本号」）→ GitHub Desktop 里写一句说明、**Commit**，再 **Push**，网站才会变
4. 不满意 → GitHub Desktop 里右键那个文件 **Discard changes**，回到改之前的样子

> 为什么不建副本：之前「清空文件夹 → 把文件复制进来 → 同步」的做法把两份分叉的历史合在一起，
> `<<<<<<<` 合并冲突标记被提交进了 `js/main.js`，线上整站点不动（§8 bug #30）。
> **在文件夹之间搬文件才是最容易出事的一步**；改动没推送之前本来就不会上线，Git 本身就是保险。
>
> 推送前顺手搜一下有没有**以 `<<<<<<<` 开头的行**（README 里写到它的这几处是说明文字，不算）；
> **永远不要复制 `.git` 文件夹**。
> Claude 不会替用户 Commit / Push，只改文件、报告改了什么。

## 3. 核心架构决策（以及为什么）

### 3.1 单一数据源 + 静态生成

`js/data.js` 是唯一数据源，定义了板块、分类、文章、角色。

`build.ps1` 读它，按这个顺序做四件事：

1. **占位图**（兜底，现在一次都不会触发）：某个 slug 若一张真图都没有，
   就从 `my web figma.svg` 里内嵌的照片现补一张 `<slug>.png`（见 §3.4）。
   已经有真图就跳过，绝不会把真图盖掉 —— 现在 46 个 slug 全有真图，这一步是空转。
2. **图片清单** `js/assets.js`：扫描 `assets/images/**`，记下每个 slug 实际存在的文件（见 §3.4）
3. **分类页**：从 `category.html` 模板生成 **18 个**，套
   `{{BASE}} {{DIR}} {{SECTION}} {{CAT}} {{TITLE}} {{DESC}}`；
   带 `to:` 的分类不生成，旧目录还会被删掉（见 §3.5）
4. **注入**：把页头 / 页脚写进每个页面 `<!-- #chrome:header:start -->` 与 `:end` 之间；
   顺手补上 `js/assets.js` 的 `<script>`（必须排在 `data.js` 之前），
   并按清单校正静态 HTML 里手写的图片路径

改了 `js/data.js` 或 `category.html` 之后重跑一次即可：

```bash
powershell -ExecutionPolicy Bypass -File build.ps1
```

> **为什么页头页脚是静态 HTML 而不是 JS 注入？**
> 早期版本用 JS 注入头尾，结果 JS 一失败页面就只剩一对空标签，
> 连导航都没有。改成静态注入后：没有 JS 也是可导航的完整站点，
> 而单一数据源靠构建脚本保住。

### 3.2 路径解析

每个页面 `<body data-base="...">`：根目录为空，`/works/artifacts/` 下为 `../../`。
JS 拼链接时一律加这个前缀，所以任何层级都指得准。

`file://` 下浏览器不会把目录地址解析成 `index.html`，
所以 `main.js` 的 `patchDirLinks()` 会在 `location.protocol === 'file:'` 时补全文件名。
部署到服务器则保持 `/works/artifacts/` 整洁地址。

### 3.3 栅格是「推导」的，不是坐标搬运

Figma 坐标不直接翻译成 CSS。优先级链条（来自用户给的提示词 §18，很关键）：

> **信息架构 > 视觉层级 > 比例关系 > 具体像素坐标**

容器 `--content: 1240px`，用 grid + gap 推导，在 1280 屏上恰好还原设计稿：

```
3 列大卡  (1240 - 44×2) / 3 = 384   ← 设计稿值
2 列列表  (1240 - 70)   / 2 = 585   ← 设计稿值
页脚 5 列 (1240 - 110×4)/ 5 = 160   ← 设计稿值
```

用户的栅格数值经核算是**精确的**，不要改容器宽度。

> ⚠ 例外：卡片间距 `--gap-card` 已从 Figma 的 44px 收到 **32px**（openai 实测约 24，取折中）。
> 这是用户明确要求「向 openai 靠拢」后的偏离，容器宽度 1240 保持不动。

### 3.4 图片路径 —— 每个 slug 一张真实照片，互不重复

`data.js` 里**不写扩展名**，只写 slug。

**现在 46 个 slug + 首页海报，一共 47 张图，全部是用户自己的照片，而且张张不同。**
换图 = **用自己的图盖掉同名文件**，不用删任何东西、不用改任何代码，
刷新一下就是新图（换成别的扩展名才需要跑一次构建，见下）。

> 为什么要「张张不同」：上一版 46 张封面全是同一批 Figma 照片的裁切版，
> 用户原话是「我自己想修改的时候无法分辨该改哪一张」。所以他在项目里放了
> `网页图片/`（85 张原始素材），现在每个 slug 都从里面挑了一张**语义对得上**的，
> 打开页面就知道哪张对应哪个 slug。**占位图这个概念现在已经没有实例了**
> —— `.placeholders.txt` 是空的，但那套机制留着（见下），万一新增 slug 还用得上。

**图源分配**（`网页图片/` → slug，挑的时候尽量对上内容）：

尺寸与裁法：

> 立绘为什么不留边：`.chars__art` 是 `object-fit: contain`，页面自己会留边。
> 生成时再补一层白底，深色的角色页上就会多出一块白方块。
>
> 为什么整批换成 JPEG：上一版 47 张 PNG 占 14.1MB，首页一屏就要拉两三兆，

>

> 关键点只有三条：EXIF 方向（`PropertyItem 274`）必须先转正，否则手机照片会躺着；
> `System.Drawing` 存 JPEG 要显式给 `EncoderParameter(Quality)`；
> `Image::FromStream` 之后那个 `MemoryStream` 不能关。

#### 占位图机制（现在没有实例，但机制还在）

`build.ps1` 只在「某个 slug 一张图都没有」时才生成占位图，并把 SHA256 记进
`assets/images/.placeholders.txt`：

- 哈希**还对得上** → 还是占位图，在清单里排到最后，任何真图都压得过它
- 哈希**对不上** → 用户已经把这张图换掉了，当真图处理

于是两种换图方式都成立：

1. **直接盖掉同名文件** —— 最省事，刷新页面即可
2. **另丢一张别的扩展名** —— 占位图会自动让位，跑一次构建即可

真实文件名由两层决定：

1. **构建期**：`build.ps1` 扫 `assets/images/**` 生成 `js/assets.js`
   （`window.JP_ASSETS`，键是 `<目录>/<slug>`）。同一 slug 有多种格式时按
   `png > jpg > jpeg > webp > avif > gif > svg` 取，**占位图一律排在最后**。
   这份清单必须**排在 `data.js` 之前**加载，构建时自动注入 `<script>`。
   构建还会把静态 HTML 里手写的图片路径（首页那几张卡、海报）按清单校正一遍。
2. **运行期兜底**：`main.js` 在捕获阶段接 `img` 的 `error`，按同一顺序换扩展名重试。
   清单过期时救场。

**日常操作**：盖掉同名文件 → 刷新页面。换成别的扩展名才需要双击 **`刷新图片.cmd`**。

> 首页那张海报 `assets/images/poster.*` 不在 slug 体系里（它不在任何板块目录下，
> 所以不进清单）。`build.ps1` 单独按 `png > jpg > …` 的顺序找 `poster.<ext>`，
> 再把 `home.html` 里那一行 `src` 对齐过去 —— 现在它是 `poster.png`（2648×1824，用户 9/12 自己换的）。
> 早先这段是写死 `poster.png` 的，换成 jpg 之后会一边找不到、一边又生成一张
> 新的占位 png，所以改成了和封面同一套规则。

> 旧的 `AUTO_FIND_IMAGES`（本地预览时主动探测同名真图）**已经删掉**。
> 它存在的理由是「占位图和真图不同名，得去探一探」；现在同名，盖掉就生效，
> 没有可探的东西了，连带那一批探测 404 也一起没了。

### 3.5 分类可以「不生成页面，直接跳转」

分类对象加 `to: '<路径>'` 就行：

```js
{ slug: 'oc', label: L('原创角色', …), to: 'characters/', desc: L(…) }
```

这样导航、移动菜单、页脚、同级分类条里的这一项都指向 `to`，
`build.ps1` 不再为它生成分类页，**并且会把之前生成过的目录删掉**（不留孤儿页）。

目前**角色板块的两项都用了**，都指向同一个地方：

| 分类 | 简体标签 | 指向 |
|---|---|---|
| `oc` | 原创角色 | `characters/` |
| `character` | **角色**（原来叫「角色关系」） | `characters/` |

也就是说：点顶栏「角色」展开后，前两项「原创角色」「角色」都直接进那个
固定深色的选角色页，而不是先看一个文章列表。
（`character` 这一项的日文也跟着从「人物関係」改成了「キャラクター」——
标签已经不表示「关系」的意思了；英文保持 `Character`。）

> ⚠ 副作用：这两个分类下的 4 篇文章
> （`strawberry-sheet` / `oc-palette` / `character-relations` / `silence-design`）
> 都没有自己的列表页了。所以角色页底部有一栏「角色相关文章」，
> 收录**整个角色板块**的 7 篇文章，保证内容仍然在站内走得到。
> 改 `to` 的时候记得一并想这件事。

### 3.5b 置顶与推荐权重（2026-10-04）

`data.js` 每篇文章第一行带两个隐藏字段，读者看不到数值：

| 字段 | 作用 | 默认 |
|---|---|---|
| `weight: 1–5` | 「继续阅读」的推荐权重 | 不写 = 3 |
| `pin: true` | 在**自己的分类页**里排最前，带「置顶」小标 | 不写 = 不置顶 |

推荐算法（`main.js` 的 `recommend()`）：候选是同板块的其他文章，
得分 = weight × 相关度（同分类 ×3；每个相同标签再 ×1.25），
然后做**加权随机抽样**（Efraimidis–Spirakis）取 3 篇 —— 分高的更常出现，
分低的偶尔也会出现，每次打开不完全一样。同板块不够 3 篇才从别的板块按权重补。
置顶只影响分类页（`byCat(..., true)`），首页和继续阅读里不带小标。

目前置顶的 4 篇（都是各自分类里**较旧**的那篇，所以效果看得出来）：
`kyoto`（摄影）、`image-read`（思考）、`map-legend`（地图）、`brush-pack`（资源）。

### 3.5c 每篇文章一个静态页（2026-10-04）

以前所有文章共用 `article.html?a=<slug>`，标题和正文都是 JS 跑起来才填进去的 ——
微信 / X / Discord 的分享卡片和搜索引擎只看得到「文章 — JasperPeng」，没有封面。

现在 `build.ps1` 用模板 `_article.html` 给每篇文章生成 `articles/<slug>/index.html`：

- **页面头部写死**：`<title>`、description、`og:title / og:description / og:image / og:url`、
  `article:published_time`、canonical（完整域名 `https://jasperpeng.uk/articles/<slug>/`，
  域名写在 build.ps1 顶部的 `$SITE`）
- **正文区先放好标题、导语、封面**：JS 没跑起来也看得到，搜索引擎也读得到；
  `main.js` 跑起来后整块换成完整文章（标签栏、日期、正文）
- **正文仍从 data.js 渲染**（`<body data-slug>` 告诉 main.js 是哪篇）——
  改了 data.js 忘了跑构建，访客看到的正文照样是最新的，只有分享卡片停在上一次构建
- 删掉 / 改名的文章，构建时旧目录自动清掉
- 顺带生成 `sitemap.xml`（60 个地址，文章带 lastmod）和 `robots.txt`

> **域名 `https://jasperpeng.uk` 写在这几处**（换域名时一起改）：`build.ps1` 顶部的 `$SITE`（文章页、分类页、sitemap、robots 都从它来），
> 以及手写页面 `index.html` / `home.html` / `characters/index.html` 头部的 canonical 和 og:url。
> canonical 写的是 Cloudflare 跳转后的地址：`/home`（不是 `/home.html`）、`/works/photos/`。

旧地址 `article.html?a=<slug>` 保留成一个跳转页（`location.replace`，不留历史），

### 3.6 顶栏展开：六块面板共用一个「舞台」

用户反馈：从一个分类移到另一个分类时，面板会**先收起再展开**，很不流畅。

根因在旧实现的结构里：六块面板各自带着自己的白底，各自用 `clip-path` 做帘幕，
`show()` 里先 `hide()` 再显示新的 —— 横移必然经过「关掉 A、打开 B」两步，
中间那一帧塌下去，看起来就是闪一下。之前靠把动画时长缩到 .16s 掩盖，治标不治本。

现在改成 **openai / apple 的做法**：白底抽出来，做成一块共用的舞台
`.menu-stage`，六块面板装在它里面：

```html
<header class="hdr">
  <div class="hdr__inner">…导航项…</div>
  <div class="menu-stage" data-menu-stage>
    <div class="menu" id="menu-research">…</div>
    …其余五块…
  </div>
</header>
```

舞台 `height: 0; overflow: hidden`，高度由 JS 量好写进 `--menu-h`。
**帘幕效果就是这个高度动画本身**，面板不用再各自裁一遍。三种情形：

| 情形 | 舞台 | 面板 |
|---|---|---|
| 从无到有 | 高度 `0 → h`（.46s） | 内容自上而下淡入 |
| **面板横移** | 高度 `h₁ → h₂` 连续补间（.34s），**透明度一动不动** | 旧的按指针方向淡出去（.2s），新的从反方向接进来（.34s） |
| 彻底收起 | 高度 `→ 0` | 淡出 |

关键点：

- `show()` 里**不再调 `hide()`**。让位的那块走 `leave()`，两件事同时发生
- 横移方向由两个导航项的先后决定，写进 `--dx`：往右滑就往右送，方向感和鼠标一致
- **收起只看「指针有没有离开顶栏」**。面板是 `<header>` 的子节点，所以导航项之间、
  导航项和面板之间怎么走都不会触发 `mouseleave` —— 用户要的「没离开导航栏就别收起」
  由 DOM 结构本身保证，不靠计时器赌（只留 120ms 宽限，给擦边走位）
- 白底那道下边线用 `box-shadow: 0 1px 0` 画，不用 `border`：
  `border` 会算进 `border-box` 的高度，和量出来的内容高度差 1px，接缝会露出来
- 让位的面板被舞台的 `overflow: hidden` 裁住，所以**高矮面板互换时不会露在白底外面**
  —— 这正是把面板放进舞台里、而不是让舞台单做背景层的原因

实测（每帧采样 `getComputedStyle(stage).height`，见 §8 的验证方法）：

```
研究 → 作品   210 → 362  透明度全程 1.00，is-on 一次没掉，高度一次没回 0
作品 → 世界观 362 → 324  同上
```

## 7. 多语言系统

四语（简 / 繁 / 英 / 日）已完整回归测试过：
切换后残留中文只剩专有名词和语言选择器本身，都是有意保留的。

### 设计

`data.js` 里用两个构造器：

```js
L(简, 繁, En, 日)   // 四语字段
P(专有名词)          // 四语同形，天然不翻译
```

**专有名词不翻译**：`JasperPeng` `嗵嗵仮面` `NooteMetro` `DOUDOU` `草莓酱/拉/祈/夏花/嗵嗵/Noote`

**翻译范围**：板块名、分类名、板块标题/导语、文章标题/导语、角色角色描述/台词/简介、全部 UI 词。
**不翻译**：文章正文（`body`）—— 保持原文，与 openai.com 一致。

**日期**不写死，存 ISO 值，由 `Intl.DateTimeFormat` 按语言格式化。
**阅读时长**存数字，由 `READ_FMT` 按语言拼量词。

### 静态 HTML 如何跟着切换

页头页脚是构建期生成的静态 HTML（写入简体文案），但每个标签带路径：

```html
<button class="nav__link" data-t="s.works.label">作品</button>
<a data-t="c.works.artifacts.label">手作</a>
<span data-t="l.contact.1.label">X</span>
```

`main.js` 的 `resolvePath()` 解析这些路径，切换语言时**只替换文本节点**，
保留同级的图标元素（下拉里的 `.arr` 箭头等）。顶栏导航项本身现在没有图标。

路径语法：

| 前缀 | 含义 | 例 |
|---|---|---|
| `s.<key>.<字段>` | 板块字段 | `s.works.label` / `s.works.kicker` |
| `c.<key>.<slug>.<字段>` | 分类字段 | `c.works.artifacts.desc` |
| `f.<key>.<序号>.label` | 下拉推荐位 | `f.works.0.label` |
| `g.<key>.<序号>.label` / `gk.<key>` | 标签胶囊 / 其标题 | `g.works.0.label` |
| `l.<key>.<序号>.label` | 联系方式链接 | `l.contact.1.label` |
| `n.<key>.<序号>.<字段>` | 说明块 | `n.contact.0.text` |
| `ui.<键>` | 纯 UI 词 | 也可用 `data-i18n="<键>"` |

首页的静态卡片挂 `data-slug="<文章 slug>"`，切换语言时由 `rerenderStaticCards()` 按 slug 重写标题和元信息。

### ⚠ 测试方法论（重要教训）

**不要用 `element.click()` 验证交互** —— 它直接派发到元素，**绕过命中测试**。
Bug #1 就是这样躲过我全部自动化测试的：测试全绿，真实鼠标一个都点不到。

正确做法：
- 用真实坐标点击（`computer` 工具的 `left_click`）
- 用 `document.elementFromPoint(x, y)` 做命中测试
- 用真实 HTTP 服务器测（预览面板会把页面转成 `data:` URI，相对路径全失效 —— 那是**预览器行为**，不是站点 bug）

**查「JS 生成的链接」要用 iframe 批量跑**（只扫 HTML 文件查不全，站里大部分链接是运行时拼的）：
把每个页面装进一个 iframe，等 JS 渲染完再收 `a[href]`，然后逐个 HTTP 校验。
iframe **必须加 `sandbox="allow-same-origin allow-scripts"`** ——
不加的话子页面会把外层窗口一起带走，测试跑一半就断了（踩过两次）。

**`iframe.onload` 会先为初始的 `about:blank` 触发一次**，不判一下就直接量，
量到的是空文档（这次因此得出「0 个 `.reveal`」，白折腾了一轮）：

```js
f.onload = () => { if (f.contentDocument.location.href === 'about:blank') return; … };
f.src = url; document.body.appendChild(f);
```

**一次别跑太多页**：67 个页面 × 每页几百毫秒会超过工具的单次执行上限。
把状态挂在 `window` 上、分批调用（`window.__sweep(25)`）就不会中途被掐断。

**要量「首屏有没有闪一下」，iframe 不能藏在 `left:-9999px`** ——
面板不显示时浏览器不合成帧，过渡不推进，读到的永远是起点值。
用 `opacity: .01; z-index: -1; pointer-events: none` 让它真的在视口里画。

**验动画不能只看首尾状态**，要每帧采样。判断「横移到底有没有塌一下」就是靠
`requestAnimationFrame` 里连续记 `getComputedStyle(stage).height` / `opacity` / `className`，
再回看那 300ms 的窗口 —— 光看动画结束后的静态值，塌不塌根本看不出来。

**扫死代码**（每轮收尾跑一遍，很便宜）：

```bash
# 未使用的 class：CSS 里声明了，但 HTML / JS / build.ps1 里一次都没出现
grep -oE '\.[a-zA-Z][a-zA-Z0-9_-]*' css/style.css | sed 's/^\.//' | sort -u > /tmp/cls.txt
cat *.html */*.html */*/*.html js/*.js build.ps1 > /tmp/all.txt
while read c; do grep -q -- "$c" /tmp/all.txt || echo "UNUSED .$c"; done < /tmp/cls.txt
```

同样的思路再跑三遍：CSS 自定义属性（比 `var(--x)` 的出现次数）、
JS 函数名（出现 1 次 = 只有定义、没人调用；IIFE 的名字是例外）、
`data.js` 的字段名（在 main.js + build.ps1 里 grep）。
**注意两类假阳性**：只出现在注释里的（比如 `.search-overlay`），
以及 `$` / `$$` 这种正则里 `\b` 匹配不了的名字。

**面板高度差 1px 会露缝**：白底和面板内容的高度必须严丝合缝。

### 加一篇文章 / 自己写正文和排版

往 `js/data.js` 的 `ARTICLES` 加一条，填对 `section` / `cat`，标题导语用 `L()` 四语：

```js
add({ slug: 'my-slug', section: 'works', cat: 'artifacts', date: '2026-09-01', read: 5,
  title: L('中文标题','繁體標題','English title','日本語タイトル'),
  lede:  L('…','…','…','…'),
  tags: [L('作品','作品','Works','ワークス')],
  body: [ { t:'p', v:'正文…' } ]   // 正文保持原文，不翻译
});
```

首页、分类页、相关阅读、搜索会自动带上。**不用改任何 HTML。**

**正文 `body` 可以怎么写**（想怎么排版就怎么排）：

```js
body: [
  { t:'p',      v:'段落' },
  { t:'h2',     v:'小标题' },
  { t:'h3',     v:'更小的标题' },
  { t:'quote',  v:'引用' },
  { t:'ul',     v:['第一条','第二条'] },        // t:'ol' 是有序列表
  { t:'hr' },                                   // 分隔线
  { t:'img',    src:'assets/images/works/foo.png', cap:'图注', alt:'替代文字' },
  { t:'figure', cap:'不给 src 就用这篇文章的封面' },
  { t:'html',   v:'<div class="随便什么">这一段原样输出，不转义</div>' }
]
```

想完全自己控排版，整篇直接写 HTML 也行：

```js
body: '<p>第一段</p><h2>标题</h2><div class="my-layout">…</div>'
```

> 除了 `html` 块和「整篇字符串」这两种，其余都会自动转义 ——
> 正文里写 `<` `>` `&` 不会出事。反过来，用 `html` 时内容由你自己负责。
> 字符串形式还能塞 `<img src="assets/images/…">`，路径从**站点根目录**算起
> （文章页在根目录，所以直接写 `assets/…` 就对）。

## 11. PowerShell 踩坑记录

- **负索引回绕**：`$arr[0..-1]` 在数组只剩 1 个元素时会**反向返回整个数组**，
  不是空数组。写路径规整（消解 `..`）时被这个坑过两次，导致链接检查器误报 200 条断链。
  改用 `System.Collections.Generic.List` + `RemoveAt()`。
- **zip 反斜杠**：`Compress-Archive` 和 .NET Framework 的 `ZipFile.CreateFromDirectory`
  在 Windows 上都会把 zip 条目名写成反斜杠，不符合 ZIP 规范
  （macOS/Linux 解压会得到一堆名字带 `\` 的散文件）。
  必须用 `ZipArchive.CreateEntry()` 手写正斜杠条目名。
- **`Remove-Item`** 在本环境某些路径下会被沙箱拦截，用 Bash 的 `rm` 更稳。
- **`@{}` 用 `.ContainsKey()`，`[ordered]@{}` 用 `.Contains()`** —— 前者是 Hashtable，
  后者是 OrderedDictionary，方法名不一样，写混了会在运行时才炸。
- **空数组和 `$null` 比不得**：`$null -ne @()` 会走数组比较的分支，不是你以为的布尔。
  想判断「加载过没有」就老老实实另开一个 `$loaded = $false` 标志位。
- **画 PNG 用 `System.Drawing`**（`Add-Type -AssemblyName System.Drawing`），
  PowerShell 5.1 自带。`Image::FromStream($ms)` 之后**那个 MemoryStream 不能关**，
  Image 对象一直靠着它读像素。
- **`Get-FileHash` 要缓存**：一次构建里同一个文件会被问好几遍（占位图判定 + 清单排序），
  不缓存就是几十次重复 IO。
- **`[int]` 是四舍五入，不是截断**：`[int](4/6)` = 1。算网格行号 / 索引一律用
  `[Math]::Floor`，否则元素会错位互相覆盖（做素材联络表时踩过）。
- **`System.Drawing` 存 JPEG 要自己给编码器**：`$bmp.Save($p, $jpegEncoder, $encoderParams)`，
  其中 `EncoderParameter([Encoder]::Quality, [int64]84)`。直接 `Save($p)` 会存成 PNG。
- **手机照片必须先按 EXIF 转正**：`Image.FromFile` 不会自动应用方向。
  读 `PropertyItem(274)`，3/6/8 分别对应 `Rotate180` / `Rotate90` / `Rotate270`，
  转完记得 `RemovePropertyItem(274)`，否则某些看图器会再转一次。
- **用 bash 的 heredoc 往外写 PowerShell 脚本时，反斜杠会被吃掉一层**：
  `-replace '\\','/'` 落到文件里变成 `-replace '\','/'`，PowerShell 报「正则表达式模式无效」。
  写路径规整这类代码时改用 `.Replace([char]92,[char]47)`，绕开引号和正则两重转义。
  （顺带：heredoc 写出来的 `.ps1` 记得**手动补 UTF-8 BOM**，
  `printf '\xEF\xBB\xBF' > x.ps1 && cat body.ps1 >> x.ps1`，否则中文路径读不出来。）

  ```bash
  grep -bo "data:image/jpeg;base64," "my web figma.svg"        # 拿字节偏移

    | tr -d '\n' | sed 's/".*//' | base64 -d > out.jpg
  ```
